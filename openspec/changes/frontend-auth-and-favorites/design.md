## Context

目前前端應用僅提供景點瀏覽功能（地圖、列表、詳情），缺少用戶認證與個人化功能。後端已完成認證 API（Email+Password 登入、JWT token、OAuth Google/Line）與收藏 API（CRUD 操作、權限控制）。本設計旨在實現前端對接，讓用戶可以登入、管理收藏，提升用戶粘性。

技術棧約束：Vue 3 + Pinia + Vue Router，後端 ASP.NET Core Web API，JWT token 存儲於 localStorage。

## Goals / Non-Goals

**Goals:**
- 實現前端認證流程（登入、登出、OAuth 回調）
- 實現景點收藏功能（收藏/取消收藏、收藏列表、狀態檢查）
- 提供良好的用戶體驗（錯誤提示、加載狀態、登入後顯示收藏）
- 確保認證狀態持久化與自動刷新

**Non-Goals:**
- 忘記密碼流程（留待後期優化）
- 個人資料編輯頁面
- 收藏分類/標籤功能
- 社群分享功能

## Decisions

### 狀態管理架構

**使用 Pinia 統一管理認證與收藏狀態：**
- `useAuthStore`：管理用戶登入狀態、token、用戶信息
- `useFavoritesStore`：管理收藏列表、收藏狀態、操作結果

**理由：**
- Pinia 是 Vue 3 官方推薦的狀態管理方案
- 集中式管理便於跨組件共享狀態與邏輯
- 支持持久化插件（自動保存到 localStorage）

### Token 存儲與刷新策略

**存儲方式：** JWT accessToken 與 refreshToken 存於 localStorage

**理由：**
- 簡單可靠，適合單頁應用
- 持久化後重新開啟頁面無需重新登入

**刷新策略：**
- accessToken 過期（15 分鐘）後使用 refreshToken 自動換新
- refreshToken 過期（7 天）則引導用戶重新登入
- API 呼叫返回 401 時自動嘗試刷新，失敗則跳轉登入頁

### OAuth 回調處理

**實現方式：**
- OAuth 回調端點：`/auth/callback/:provider`
- 回調後從 URL 取得 code，呼叫後端交換 token
- 成功後儲存 token 並跳轉原請求頁面

**理由：**
- 避免前端直接處理 OAuth 流程（安全最佳實踐）
- 後端統一處理 token 交換與用戶創建

### 路由守衛設計

**認證守衛 (`requireAuth`)：**
- 保護需登入頁面（收藏列表、個人中心等）
- 未登入時重導向至登入頁，登入後返回原頁面

**理由：**
- 前端守衛提供良好的 UX（後端仍強制驗證）
- 避免 API 呼叫失敗後才顯示登入提示

### 收藏狀態同步

**樂觀更新策略：**
- 用戶點擊收藏按鈕立即更新 UI 狭態
- API 調用失敗則回滾狀態並顯示錯誤

**理由：**
- 提升響應速度，改善用戶體驗
- 減少等待感，移動端尤為重要

## Risks / Trade-offs

### 風險：OAuth 回調 URL 配置錯誤

**風險：** OAuth 提供商拒絕回調或回調到錯誤端點

**緩解措施：**
- 開發環境使用 localhost:5173
- 生產環境需配置正確的 domain
- 提供 OAuth 設置文檔與檢查清單

### 風險：Token 過期處理不完整

**風險：** 用戶操作中 token 過期導致失敗

**緩解措施：**
- API 攔截器統一處理 401 響應
- 自動刷新失敗則跳轉登入頁
- 刷新中暫停其他 API 請求

### 風險：收藏狀態不一致

**風險：** 前端樂觀更新與後端實際狀態不同步

**緩解措施：**
- 錯誤時回滾狀態並顯示提示
- 進入收藏列表頁時重新從後端獲取
- 提供手動刷新選項

### 權衡：localStorage vs Cookie

**選擇：** 使用 localStorage

**理由：**
- 實作簡單，跨域要求較低
- 配合後端 JWT 設計，無需 CSRF 防護

**缺點：**
- XSS 風險（需確保前端代碼安全）
- 無法設定 HttpOnly

## Migration Plan

1. **建立基礎架構**
   - 安裝 Pinia、配置路由
   - 創建 authStore 與 favoritesStore
   - 建立 API 客戶端函數

2. **實作認證功能**
   - 登入頁面與表單
   - OAuth 回調處理
   - 路由守衛

3. **實作收藏功能**
   - 收藏按鈕組件
   - 收藏列表頁面
   - 與景點頁面整合

4. **測試與優化**
   - 手動測試認證流程
   - 測試收藏 CRUD 操作
   - 優化錯誤處理與用戶提示

## Open Questions

   - 建議：獨立路由便於實作與測試

2. **OAuth 按鈕位置：** 僅在登入頁還是全站顯示？
   - 建議：登入頁優先，後期可考慮頁首快速登入

3. **收藏上限：** 是否限制單個用戶收藏數量？
   - 建議：本期不設限，後期根據性能監控決定
